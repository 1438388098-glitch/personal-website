## 1. 目标与定位

**一句话目标**：把只有简历功能的单页网站，重做为信息密度大、栏目多、干货实的个人品牌站。

**定位（人设）**：胡圣炜（GitHub 显示名 Stoic，笔名艾苇），中南财经政法大学法学本科在读（2023.09–2027.06），自学工程师，主打「法律 × AI：可复核、可评估、懂边界」。与 GitHub Profile 叙事一致：法律场景 LLM 应用实践。

**受众优先级**：法律科技/AI 方向的 HR 与面试官 > 同行与网友 > 自己（沉淀工具）。

**设计基调**：编辑风 + 工程理性。高信息密度（5-6/10）、低动效（3/10）、克制变体（5/10）、单一强调色。全站视觉原则：可验证、不吹牛——真实数字、真实指标、真实进度；数字必须来自真实仓库的公开指标并注明来源与日期，禁止编造。

**成功标准**：
1. 陌生人 30 秒内感知到「会用 AI 造工具的法学生」这一差异化人设；
2. 每个主推项目都有「问题/边界/机制/验证」案例页与真实指标；
3. 站内有可持续更新的内容引擎（Markdown 即内容），而非一次性摆拍；
4. Lighthouse 性能/SEO/无障碍达标。

## 2. 信息架构

```
/             首页：定位宣言 + 真实数字条 + 三大入口 + 最新动态流
/projects/    项目作品集：法律主线 / 工程侧证 / 实验 三个分组
/projects/<slug>/   项目案例页（case study）
/blog/        文章列表：法学随笔 / 技术笔记 / 工程方法论
/blog/<slug>/       文章页
/exam/        法考备考专栏：进度看板 + 方法论 + 错题笔记
/notes/       读书笔记/知识库：按书与主题归档的轻量数字花园
/now/         Now 页：现在在做什么（月更）
/toolbox/     工具箱：自用工具与开源小件（仅列公开仓库，链 GitHub）
/about/       关于 + 完整简历 + PDF 下载（简历功能保留于此，含简历预览）
/poems/       诗集《陌生的你》：保持现有独立站不动，导航与页脚留入口
```

导航主栏：项目 / 博客 / 法考 / 笔记 / 工具箱 / 关于；Now 与诗集放页脚与首页动态区，避免导航超载。

## 3. 页面设计要点

### 3.1 首页（信息密度担当，首屏一屏内）
- **Hero（左对齐不对称）**：一句话定位「法律在读 × 自学工程师：我在给法律场景造可复核的 AI 工具」；CTA 两个（看项目 / 下载简历）；状态一行（备考法考中 · 武汉）。遵循 design-taste-frontend 的 hero 纪律：标题 ≤2 行、副文 ≤20 词、无滚动提示语、眉标全站限量。
- **真实数字条**：公开项目数、评测题量（如 cn-judbench 323 题）、检索 Recall@5（statute-rag 98.9%）。上线前逐项核对仓库现值并注明「数据截至」。
- **项目精选**：2-3 张案例卡，不对称网格（禁三等分卡片）。
- **最新动态流**：最近文章 3-5 篇 + 法考进度条 + Now 摘要一段。
- **页脚**：GitHub / 邮箱 / 知乎 / 微信二维码 + 诗集入口 + RSS + 备案/版权。

### 3.2 项目案例页（模板固定，内容各异）
统一结构：一段话摘要 → 问题与边界（不做什么）→ 机制（架构图/流程）→ 验证（指标表 + 已知失败案例）→ 链接（GitHub / 演示）→ 免责声明（非法律意见）。frontmatter 携带 `metrics` 数组用于首页与列表页数字条复用。

### 3.3 法考专栏
进度看板（科目 × 状态，静态数据，改 Markdown 即更新）+ 方法论文章 + 错题笔记（zhuma-fakao-review 产出可直接入库，注明脱敏）。

### 3.4 关于页
人话自我介绍（成长背景、粤北多语言环境、阅读写作志愿）+ 结构化简历（教育、经历、技能、荣誉，迁移旧站内容）+ 简历 PDF 下载与预览。PDF 以静态文件置于 `public/`：实施 M1 时从网页简历内容导出一次，此后每次修改简历内容时同步重新导出（维护手册写明这一步）。

## 5. 技术架构

### 5.1 框架与工程
- Astro 5 + TypeScript + 内容集合（content collections，zod schema 校验）。
- 参考 astro-paper / astrofy 的成熟实现（布局、RSS、标签、分页），视觉完全自定义（实施阶段以 design-taste-frontend skill 为设计准绳），不长模板脸。
- Git 纪律：新仓库 `git init`、`.gitignore`（node_modules/dist/.astro/.env）、README（如何运行/测试/写内容）、小步中文提交。

### 5.2 内容集合 Schema（概要）
- `projects`：title、slug、group（法律主线/工程侧证/实验）、summary、metrics[]、links、date、featured。
- `posts`：title、slug、category（法学随笔/技术笔记/工程方法论）、tags、date、draft、lang。
- `notes`：title、book/source、theme、date、status（在读/读完）。
- `exam`：date、subject、type（方法论/错题笔记/周记）、progress 相关字段。
- `toolbox`：name、repo、description、public（仅允许 true）。
- `now`：period、items（单独 JSON/MD 文件亦可）。

### 5.3 功能实现
- 搜索：Pagefind 静态索引（构建期生成，无后端）。
- RSS：@astrojs/rss 全站源。
- 暗色模式：跟随系统 + 手动切换；字号无障碍调节保留旧站能力。
- 联系：邮箱 + 微信二维码 + GitHub + 知乎；无表单、无后端。
- 留言表单、大模型实践 token 统计（旧站恒显 "--"）：砍。旧站「Agent 引用」介绍内容并入工具箱或一篇技术笔记。

### 5.4 双语方案（用户拍板保留）
- Astro 内置 i18n 路由：默认中文 `/`，英文挂 `/en/` 前缀。
- UI 文案（导航、按钮、页脚）全量双语；**内容文章中英双写不强制**：英文版缺失时回退中文并在语言切换处标注「仅中文」，避免每篇双倍维护。翻译优先级：首页、关于/简历、项目精选页。

### 5.5 部署
- 静态构建产物，部署到现有 Cloudflare 托管链路（现有站 `Server: cloudflare`；具体走源站 nginx 还是迁 Cloudflare Pages，在实施 M1 时确认源站访问方式后定，默认沿用现有方式直接替换）。
- `/poems/` 现有目录不动，部署时排除覆盖。
- **公网替换旧站前单独向用户确认**（发布公网先确认）。

## 6. 错误处理
- 构建期：content collection zod 校验，frontmatter 缺字段/类型错误直接构建失败（第一道测试）。
- 运行期面窄（静态站）：自定义 404；外链 `rel="noopener"`；图片懒加载与尺寸预留（CLS<0.1）。
- 内容红线校验：构建脚本扫描站内产出物中 `sk-` 等密钥特征串，命中即失败。

## 7. 测试与验收
1. `astro build` 零错误 + schema 校验全绿（冒烟基线）；
2. 内链死链检查脚本（构建产物全站 crawl）；
3. 密钥/敏感串扫描脚本；
4. Lighthouse：性能 ≥90、SEO ≥95、无障碍 ≥95（移动端）；
5. 渲染页面视觉验收（逐页 PNG + 视觉评审，明暗双模式）；
6. README 写清：如何运行、如何新增一篇文章/项目/笔记（内容维护手册）。

## 9. 风险与开放问题
- **双语成本**：内容不强制双写（§5.4），若后续发现英文版长期无人维护，可降级为仅 UI 双语。
- **指标时效**：数字条数据需在每次大改版时与仓库现值核对，页脚注明数据截至日期。
- **源站访问**：部署方式依赖现有服务器/Cloudflare 配置细节，M1 时确认。
- **诗歌站兼容**：`/poems/` 独立运行，部署流程不得覆盖该路径。
