## 问题与边界

法学论文的推理结构因文体而异：判决书评析要按裁判逻辑走，立法建议要按问题、方案、理由走。JurisCoT 把六类文体的推理链做成模板资产，输入法律问题加文献、法条、案例、数据、域外法，输出结构化推理链与学术正文段落，设计为 LawAutoPaper 的核心推理组件。边界直说：v0.1 只覆盖模板资产管理（list / show），模型推理管线在 TASKS.md 排期里尚未实现，run 入口对「能不能跑」的两种情况都给诚实退出码，不伪造成功。

## 机制

提示资产分层：base 目录放角色设定与法律论证规则，cot 目录放逐步提示（含变体），templates 目录放六类文体的 YAML 链模板。测试覆盖两类：模板完整性（六个模板全部可解析、字段齐全、每个链步骤都有配对提示文件）与 CLI 行为（list / show / run 的成功与错误路径，退出码 0 / 2 / 3 分别对应成功、配置错误、功能未实现）。

## 验证

v0.1 还没有模型生成质量数字，能验证的是资产与 CLI 的正确性，且全部自动化：模板完整性测试检查六个 YAML 模板可解析、字段齐全、每个链步骤都有配对提示文件；CLI 行为测试覆盖 list / show / run 的成功与错误路径。测试用 python -m pytest tests -q 一条命令跑完。生成效果的检验标准已经写进 TASKS.md 第 38 至 40 天，共四项验收：六种模板各跑一次，JSON 解析成功率不低于 95%；推理完整性要求学说不少于 2 个、评析含理论依据、解释力、局限三个维度；引用可溯源要求每个学说标注来源 chunk_id；一致性要求同输入连跑 3 次、4c 立场保持一致。这四项属于推理管线实现后的验收排期，目前一项都没执行，所以本条目不提供任何生成质量数字，只报告资产校验结果。

## 已知失败

推理管线未实现：prompt_loader、pipeline、engine 排在 TASKS.md 第 29 至 37 天，run 目前只是占位入口，无 API key 时以退出码 2 报错，有 key 也只以退出码 3 如实告知功能未实现。提示资产未经模型实测：TASKS.md 第 9 至 26 天安排的逐步测试（例如 step1 用 3 个不同部门法问题各跑一次、step2 检查法条引用只来自注入列表）全部未勾选，提示词目前只通过结构校验，没有生成质量证据。复现有外部依赖：链路依赖本地法条库共 263 份文件，路径不入库，别人拿到仓库无法跑完整流程。覆盖面有限：只有 6 类论文模板，6 类之外的文体没有推理链可用。模型输出的波动被预先承认：验收标准专门设了同输入 3 次跑立场一致的检查项，说明作者预期一致性不能默认成立。
