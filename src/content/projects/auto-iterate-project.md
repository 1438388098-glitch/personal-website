## 问题与边界

让 Agent「持续改进这个项目」通常死在两种结局上：要么闲置说没活可干，要么没有验证地空转。这个技能把循环接管成确定性的：可见待办、逐候选验证、批量提交、硬早停门禁、反闲置契约。边界：git 是唯一外部依赖，绝不重写历史、默认不推送、拒绝把用户已有的改动吸收进自动提交，密钥模式扫描跑在每个暂存 diff 上。预算四维度（轮数、分钟、token、绝对截止时间）可在运行中改。

## 机制

一轮五步：check（确定性停止条件与预算）、mine（七个扫描器把仓库事实变成带证据的候选，判断式深度扩展按 16 个透镜轮换、永远不做第一波）、rank（按每轮期望价值打分，带多样性配额、价值下限、依赖解锁与透明的分数明细）、implement 到 verify 到 commit（每个候选独立成单元，提交前必须全量验证）、record（轮历史、token 账目、每 10 轮阶段报告、收尾回顾）。状态自持在 .autopilot 目录，可恢复、可迁移，每次写状态留一代备份；「目标全达成」的停止条件在存在未验证目标时拒绝生效，有真实工作未完成时 finish 会被拒绝。另带一个 127.0.0.1 只读观察面板：演化树旁排每轮卡片流，可回放。

## 验证

被测对象是那个确定性 helper：scripts/autopilot_state.py，Python 3.6+，仅标准库，循环里的每个决策都经它落盘。测试套件 README 口径约 190 例，本地按套件自己的统计表达式清点为 209 个测试方法；CI 在 Python 3.8 与 3.13、Ubuntu 与 Windows 四个组合上跑全量，另有 --smoke 快检，约 15 秒跑完一轮视机器而定的轮循环检查。套件自带一个元守卫用例：收集到的用例数必须等于源码定义数，否则构建失败；起因是曾有两个测试类重名，第二个静默遮蔽第一个，14 个用例在套件全绿的情况下一次都没跑过。安全路径有账可查：密钥扫描覆盖 AWS、私钥、GitHub、Slack、Google、sk-*、JWT 等模式，sk-proj- 与 sk-ant- 形态曾漏报，修复后补了 8 模式参数化测试；config.json 写入 SHA-256 指纹，被篡改时 check 会告警。项目对自身做过一轮六维度审查（U-01 到 U-49），修复记录写明每批改动的验证方式：全量测试加手动端到端场景（init、backlog、begin、commit、complete、check、finish，外加密钥脱敏与路径守卫），当时基线 155 用例全绿；审查还顺带补上了此前缺失的 CI。1.6.0 这个版本，是让它对自己的仓库跑了一整夜迭代出来的。

## 已知失败

token 预算是估算值：从 diff 推算，公式为每轮 500、每行文本 12、每个二进制文件 100，并非 LLM 实际用量。Deep Expansion 的 subagent 开销发生在子会话里，diff 看不见，所以另设 max_expansion_waves 作为上限护栏；文档明说，无上限时一次运行可以花超所有已配置预算，而 check 仍报健康。观测面板的 token 统计同样是「变更等价」代理指标。验证门禁有一个文档承认的盲区：check_commands 若把输出经 tail、head、grep 管道转发，退出码取自管道最后一个元素（恒为 0），测试全挂也报绿；troubleshooting 要求用户敲坏一个测试来证明门禁真的有效。判断式扩展依赖宿主 runtime 提供 subagent 工具，没有时退化为进程内逐镜头串行，能力打折。六维度审查留下 20 项 P3 待办，按「触碰某文件时顺手清理」处理，不单独立项。
