5月8日，国家网信办会同发改委、工信部发布《智能体规范应用与创新发展实施意见》，这是监管第一次系统性地给智能体立规。有清华学者在解读里给了一个很准的概括：中国的AI监管，正在从管模型走向管行动。

我看到这条新闻的第一反应有点奇怪：欣慰之余觉得眼熟。我写过一个让 Agent 通宵自迭代 Git 仓库的工程，最长一次跑了 20 轮，摸排、挑活、编码、验证、提交，循环到天亮。把实施意见里要求的每件事，跟我实际写过的防线逐条对下来，发现监管文件描述的那些制度，工程师早就开始在代码里给自己扎了。

## 监管要注册留痕，我的做法是让每一步可审计

意见提出探索智能体注册平台，提供数字身份管理、能力声明等服务。

我的版本朴素得多：每次自动迭代启动时生成一个 run_id，所有工作隔离在以这个 id 命名的独立分支上，状态写进 state.json，每个动作（开工、提交、回滚、改配置）追加进 log.jsonl。第二天早上我想知道 Agent 昨晚干了什么，不用翻终端回滚，读那两个文件就够了。

注册制度解决的是同一个问题：一个无法事后审计的行动者，不值得信任。这条对国家监管和对我自己，是同一句话。

## 监管要授权范围，工程上叫越界即拒绝

意见要求确保用户对智能体自主决策享有知情权和最终决策权，执行操作不得超出用户授权范围，还把「仅限用户本人决策、需用户授权决策、智能体自主决策」三个边界分开了。

这一条我的工程里落得最实，拆成三道闸：

- **危险动作黑名单**：重置历史、强制推送、改写提交，这些写进系统级禁令，模型自己想去碰也会被工具层拦下；
- **外发默认关闭**：推送远端这类对外动作，默认禁止，必须主人显式打开配置才放行；
- **爆炸半径上限**：单轮改动超过约定规模就必须拆分，防止一轮失手带走整个仓库。

至于最终决策权，我的设计里压根没交给模型。预算（截止时间、最大轮数、token 上限）全部是主人写死在配置里的，模型不知道什么时候该停，也不该由它来决定。让它自己判断停机，早期的死法之一就是它宣布「没有活了」然后干耗到超时，这个坑我之前写过，不再展开。

## 监管要分级治理，工程上叫验证分级

意见说根据应用场景和潜在影响，审慎稳妥开展分级治理，准入、测试、备案、审计、召回按场景强度配置。

翻译成工程语言：验证的厚度要跟动作的危险程度成正比。我的自动迭代是两级验证：普通轮次只跑轻量检查（语法、类型，秒级），到验证里程碑和提交轮再上全量（测试套件、类型检查、完整构建）；提交前额外过一遍秘密扫描，密钥这类东西永远不该进版本库。

出了问题怎么召回？我的答案写进了工具名：undo-round。改坏一个提交，用 git revert 正向抵消，历史只前进、永不重写。召回的成本越低，放手让 Agent 干的心理门槛就越低，这两件事是配套的。

## 监管问责任，工程先问爆炸半径

意见要求使用者承担安全使用、合法使用和审慎授权的责任。这条我完全赞成，而且想补一个工程师视角的注脚：责任大小，取决于爆炸半径。

我的自动迭代目前跑在本地、单人仓库里，最坏结果是明天早上我自己头疼一小时。同样一套东西要是接到生产系统、替用户操作真实数据，性质就全变了。诚实地说，我的 Agent 现在在我机器上拥有完整的 shell 权限，这在个人项目里是效率选择，放到意见设想的场景里完全不可接受。文件里说的权限沙箱、按场景的准入门槛，正是从玩具到生产之间缺的那块板。

## 结语

有个次序值得玩味：工程实践先出现，监管文件后到，像是在给全行业的工程清单盖章。实施意见还是政策指引，条款尚粗；上一个拟人化互动办法从公布到落地只隔了三个月。从管说的话到管做的事，过渡期大概就是今年。

对写 Agent 工程的人来说，最好的准备没有别的版本：把自己的笼子先扎好。哪天细则落地，你会发现里面大部分条款，你在自己的代码里早就见过。
