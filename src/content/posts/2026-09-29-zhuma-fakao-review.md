备战法考时，错题本是考生手里最值钱的个人资产。我的竹马法考账号里攒了 1,655 道错题，但直接在 App 里刷错题，体验其实很碎：题目是按做题时间或章节散乱铺开的，同一个考点可能零散分布在几十道题里；解析折叠在点击层下方，来回翻找很难形成连贯的记忆体系。

于是我写了 `zhuma-fakao-review`，用一条自动化流水线把整套错题库抓取、聚类、提炼，最终排版成一本可以直接打印背诵的分科 PDF。

## 七段处理流程

整套工具尽量减少对平台的侵入：

1. **认证与抓取：** 本机浏览器扫码登录一次，保存本地 Profile 后续复用。抓取过程只调三个只读接口，全程单线程串行限速，带指数退避和失败熔断，避免给对方服务添乱。1,655 道题抓完大概用了 9 分钟，中途随时中断都能断点续传。
2. **学情问答：** 启动任务前，脚本会先问几个关键问题：哪个科目最弱、当前是第几轮复习、离考试还有几天、每天能背几小时。这些学情数据会直接写进后续所有 Agent 的 Prompt 里。比如针对薄弱科目，生成的知识点篇幅会自动放大 1.3 到 1.5 倍；如果距离考试不足一个月，每科开篇还会直接收敛出最优先背诵的 TOP 5 考点。
3. **考点归并：** 摆脱以"题"为中心的视角，改为以"知识点"为最小单元去重合并。被考过多次的高频易错点自动打上标签，考查频次直接决定展开的详略程度。
4. **排版输出：** 最终渲染为按学科分册的 PDF 和一本百余页的合辑。针对黑白打印机专门调了对比度灰度，重点易混淆点配了浅蓝高亮块，带着原生书签与跳转目录。

## 既然用来背，就容不得半点错

给考生背的笔记，如果中间有大模型胡编乱造或者法条张冠李戴，后患无穷。

在生成阶段，我设计了"科目 × 维度"的交叉审校：把生成好的内容分派给不同的子 Agent，分别盯紧**法条准确、答案一致、要点覆盖、排版格式、学情适配、章节衔接**这六个维度。每个审校节点职责单一，发现的 P0 级法理错误必须强制打回、重写、复审。

这里我还给自己加了一道"防假绿灯"门禁：很多自动化脚本最容易犯的错误，就是上游抛了异常或者格式解析失败，聚合脚本却当作"没有问题"直接跳过。我给合并逻辑写死了检查：**只要下游报告没被完整解析，脚本立即以非零错误码硬崩溃，绝不允许产出一份看似岁月静好的假报告。**

## 跑在合规与安全的边界内

项目写完后，我按惯例做了一轮自审，结果当场打脸：我发现前期的登录脚本把带有 256 位认证 Token 的状态明文保存在了一个冗余临时文件里。虽然没有往外发，但属于纯粹的安全漏洞，定级高危后立刻删掉，把认证态完全收拢在本机隔离 Profile 中。原本我给自己打了个 95 分的高分，复查后主动在审计文档里扣到了 90 分。

边界同样在 README 里摆得清清楚楚：工具只处理自己合法账号内的个人错题，接口纯只读；生成的笔记仅限个人离线学习，不分发题库原题。

做完这套流程最大的体会是：给大模型做应用工程，不要迷信"一句话生成"的黑盒奇迹；把边界约束住、流程切细、把失败显性化，出来的东西才真的敢往打印机里送。
