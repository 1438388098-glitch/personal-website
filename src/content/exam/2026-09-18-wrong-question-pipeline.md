## 问题：错题的价值在复习，不在收藏

一段时间下来，错题本先变成了仓库：竹马后台躺着 1655 道错题，每道题只记录「你做错了」，连你当时勾了哪个选项都没保存，更不会替你归纳这些错题背后反复出现的知识点。手工整理不可持续：一千多道题逐题抄写、归类、补易错易混点，做完一轮考前也复习不完，整理的热情通常撑不到第二轮。所以目标从一开始就不是「再整理一遍」，而是一条可重复执行的管线：把错题本里的全部错题变成按科目分册、可直接背诵的知识点笔记 PDF，从错题反推反复考的重点，补上易错易混点；除了扫码登录和回答一份学情问卷，全程由 Agent 自主编排脚本与 subagent，不需要人工干预。

## 机制

管线分五步。第一步全量抓取：走竹马内部只读接口，不交卷、不动作答记录，拿到题干、选项、正确答案与完整官方解析，这是页面爬取拿不到的信息密度；断点续跑、原子落盘、熔断退避，中断了重跑即可。第二步切分单元：按科目切分，每个科目最多 250+ 题，会被切成不超过 55 题的单元，交给并行 subagent 分别处理。第三步生成笔记：先问学情（薄弱科目、复习轮次、距考天数、每日时长、习惯、目标），笔记按知识点（而非题目顺序）合并去重，并标注每个知识点「考查 N 次」。

第四步六维审查：笔记生成后由多个 subagent 按「科目 × 维度」并行审查（法条准确性、答案一致性、覆盖完整性、格式合规、学员适配、跨单元衔接），汇总成修订清单，P0 问题必须修订并复审；汇总脚本内置防呆，解析不出问题条目时直接报错，绝不产出「无需修订」的假绿灯。第五步装订：先审查修订、后渲染交付是脚本的强制顺序，产出单科分册加可选总册（封面、目录、PDF 书签跳转），三档排版密度，易错易混点以浅蓝色块呈现，整套样式灰度安全，黑白打印下标签与层级仍可辨。

支撑这一切的是几条工程底线：JSON 落盘原子写、进程锁防并发、登录态只存本地浏览器 profile、subagent 提示词内置防注入与写入路径白名单。实现细节与安全审计的展开，见项目案例页 [zhuma-fakao-review](/projects/zhuma-fakao-review/)。

## 验证

一次完整运行的实测规模：18 个科目（客观题一 9 + 客观题二 9）、180 个有题章节；唯一错题 1655 道（章节预期合计 1661，差值是跨章节重复的题，按 id 去重）；41 个处理单元，抓取约 9 分钟。笔记由 39 个 subagent 五批并行生成，另 2 个单元因 429 限流由主 Agent 手写。最终产出 18 份单科 PDF 共 8.3MB，外加 129 页总册 4.2MB。

管线自身的质量也有底线：npm test 共 22 例，覆盖参数解析、原子写、进程锁过期抢占、切分单元与 manifest，以及假绿灯防护（有审查报告但零解析必须以退出码 2 失败），全部基于临时目录的 CLI 端到端验证；仓库另经两轮独立代码审查加复审验收，过程留痕于 git 历史与安全审计文档。

## 边界

这条管线只处理本人账号的真实错题：对平台只读（不交卷、不动作答记录），串行抓取且默认 150ms 间隔。错题内容与学情会作为提示词发送给所使用的模型服务商，这是整条管线仅有的两条出本机数据通道之一，另一条只在把总册 PDF 复制到云同步范围内的桌面时发生。

输出是背诵笔记，不是知识本身：笔记从错题反推，覆盖的是反复考、易错易混的知识点，它替代的是手工整理，不是做题、订正与思考。六维审查由 LLM 驱动，修订清单能拦住 P0 级问题，但不等于零遗漏的保证。

已知的失败如实记录在项目 README 的「已知限制」里：接口拿不到「我的错选」，只记录哪些题错了，不保存当时的选项；仅覆盖客观题，主观题错题本结构不同，未适配；依赖竹马内部接口，前端改版可能失效；登录态会过期，需重新扫码；总册 PDF 中各单元章节编号彼此独立，会出现编号重起，已用「第 N 部分（续）」缓解。
