## Problem and boundary

For treaties, codes, judgments and government reports the difficulty of translation is length: across hundreds of pages terminology must stay consistent, citations like § 1983, 5 U.S.C. § 552 and Miranda v. Arizona must survive verbatim, and no page may be dropped. This skill splits long documents into chunks translated in parallel; each chunk's subagent writes new terms to its own file before a central merge, avoiding write races on a shared file. Boundary: scanned and encrypted files are out of scope (OCR and decryption are needed; the script warns explicitly); translation quality depends on the underlying model. Citations get a review pass and terminology a script backstop, but professional use still warrants a human final read.

## Mechanism

An eight-step pipeline: extract (auto-strip headers, footers and page numbers; detect tables) → pre-build the glossary → chunk → parallel translation → glossary merge → hard completeness check → merge and review backfill → render the Chinese PDF (auto-picking a system Chinese font, generating a table of contents, fitting table column widths). The glossary has five groups (institutions, statutes, cases, doctrines, common words) and is the single source of cross-document consistency; the apply_glossary script deterministically backfills residual English terms in the translation into the "中文 (English)" form. The examples directory holds an end-to-end sample on public-domain text (US constitutional amendments and § 1983) with a real quality table and one by-design length-ratio warning explained.

## Verification

Pipeline quality is enforced by script-level hard checks, with numbers public in the examples directory's end-to-end sample (public-domain text: US constitutional amendments and 42 U.S.C. § 1983; the source PDF is generated by script, reproducible). Page coverage 2/2 with check_completeness passing: page-marker set equality is a hard check and a missing page fails with exit code 1. A translation/source length ratio below 0.25 or above 1.6 logs a warning; the sample's chunk_002 triggered one WARNING (ratio 0.12) because the last page holds only 1.5 lines, a by-design false positive noted in the quality table. Terminology consistency: the two chunks' glossary files merged to 16 entries with 0 conflicts (first registrant wins); residual English terms in the translation were then backfilled deterministically by apply_glossary. Citation fidelity: 42 U.S.C. § 1983 and Amendment I/XIV survive untranslated and unrewritten. Cross-chunk continuity: chunk 1's last sentence was cut at a page boundary and chunk 2's translation completes it from the carried context; the context block did not leak into the translation. Tests run with python -m unittest discover -s tests, 6 cases covering glossary merge rules (base table first, first registrant wins, conflict warnings), missing-page exit 1, the length-ratio warning path, merge ordering and page-marker stripping, and missing-translation errors. The sample quality table also states its scale, N=1 document / 2 pages: it proves the pipeline works, not batch statistics over long documents.

## Known failures

Scanned PDFs are out of scope (OCR needed; the script warns only), and encrypted files must be decrypted first. The length-ratio heuristic false-positives on documents whose last page holds little content (sample chunk_002 is exactly that); human verification then release is a designed step. Table reconstruction has a version dependency: below PyMuPDF 1.23.8 table detection degrades to heuristics, and complex layouts (cross-page merged cells, nested tables) may not rebuild fully; and since the sample document has no tables, headers or footers, the table-to-Markdown and header-stripping features are not demonstrated end to end. Translation quality finally depends on the model used: citations get review re-checks and terms get script backfill, but professional use still warrants a human final read.
