## Building

This round pushed statute-rag from "local retrieval foundation" to something actually usable. The corpus grew to 25,987 provisions across 444 statutes; after semantic reranking there is now a LLM precision layer: the pipeline's top 50 candidates go to a judge model, which lifts the 5 most relevant to the top. On the blind holdout set (100 questions, question writers fully isolated from the system) recall@5 rose from 66.0% to 92.0%. Production currently runs the judge model Jev (paid tier, about 1.3 seconds and $0.00037 per question); the free tier times out on long-tail requests (429 rate limits) and stays a fallback. The retrieval page is live: [iweistoicqc5.top/law](https://iweistoicqc5.top/law/); the "precision rerank" switch next to the search box controls whether the LLM layer runs.

The demo server cannot host the semantic layer (2 cores, memory exhausted and into swap; the three models need about 1.6GB), so the online demo runs only the lexical and LLM-rerank layers, scoring 57.0% on the same holdout set (measured with the free chat judge; the corpus and config are unchanged since the switch to Jev, which has not been re-measured online, so I won't pre-credit it a number). The gap is all in recall: the rerank layer rescued every one of the 57 questions the lexical layer found, none lost, while 43 were never retrieved at all. Either add memory for the semantic layer, or accept the reduced setup and label it honestly.

## Exam prep

Bar exam prep continues. The wrong-answer pipeline is in place: one full run processes 18 subjects, 41 units and 1,655 unique missed questions, about 9 minutes per scrape, producing 18 notebook PDFs ready for recitation. Scale and method are documented in the [exam section](/en/exam/).
